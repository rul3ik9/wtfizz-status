Reviewed top to bottom on 3 September

Four parallel reviews — safety and cheating, all 35 parts against the design document, performance, and brand copy. Five faults were found in the farm loop and fixed the same day; 26 findings remain open. Each one below says whether the build team can act now or whether it is waiting on you.

Of the 26: sixteen can be done today with nothing blocking them · seven need a decision or an approval from the brand owner · two need an art instruction · one cannot be settled without testing on a real phone.

Against the design document: 20 of the 35 parts match, 5 do not, 10 match in part, and nothing is missing entirely. No safety or cheating problem of any severity was found, and everything players can currently read passed the brand check.

⚠ One thing to know before reading anything below

Nobody has played the game yet. Everything on this page was checked by opening the game up and inspecting it piece by piece — every rule, every number, every screen. That proves the game is built correctly. It proves nothing about how it feels, or whether it runs smoothly on a real phone with real players in it.

So read every DONE as "built and checked, not yet played." A test session on a real phone is the step that closes this gap, and it has not happened.

Fixed during this review — the farm loop did not match the design document

The owner asked whether the build followed the documented tea-plant cycle. It did not, in four ways, and two of them let resources appear out of nothing. All four are now fixed and verified. Recorded here because they show what a review is for, and because the reward numbers below depend on them.

#What was wrongWhy it matteredState
F1 A can could not be poured on a plant that was waiting for water, or on one still growing — only on a fully grown plant. The design document calls the water-or-pour choice the core of the game, the one decision that repeats every round. It did not exist. FIXED

Three claims in this review were wrong, and were caught by re-checking the game

A reviewer reported that progress saves only every five minutes, breaking a core promise. It does not — the five-minute figure belongs to a third-party component the game does not rely on; the game runs its own 30-second save loop. The promise holds.

An earlier note on this page said the forbidden-word-pairing list was empty. It is not — it holds four pairings, all for monster names. The real gap is narrower and is now recorded correctly as M4 above.

And the fix for F3/F4 introduced F5, a way to lose a player's earned leaves. The review caught it the same day, before anyone played it. It is listed as a fault above rather than quietly folded into the original fix.

All three were caught the same way: by measuring the running game instead of trusting a summary. That is the standard this page is held to.

Keeping this page honest

🔄 This page gets updated every time anything changes

This is the one place to look for where the project stands. A part of the game is not finished until this page says it is — an out-of-date status page is worse than none at all, because people believe it.

The rule: whenever a part changes status, or something starts or stops blocking progress, this page is updated and republished the same day. Never saved up for later.

How it gets updated

  1. Check the actual game first. Never write a status from memory or from our own notes — those have already been wrong twice.
  2. Update the row, and anything elsewhere on the page it affects.
  3. Update the counters at the top and the date in the header.
  4. Publish. The page goes live within about a minute.

The standards this page is held to

  • Measured, never guessed. Every number came out of the running game. If something cannot be measured, the page says so instead of estimating.
  • A green row is a promise. "Built but never played" does not count as finished without the warning at the top of this page.
  • Differences from the design document get written down, not quietly absorbed. Two are recorded above — the island layout and the spare-item rates — and both ship knowingly.
  • When our notes and the actual game disagree, the game wins and the notes get fixed.
