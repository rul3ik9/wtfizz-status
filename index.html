Update protocol

🔄 This page must be republished whenever any system changes state

This site is the single status surface for the project. A system that is finished, started, blocked, or unblocked is not finished until this page says so — a stale status page is worse than no status page, because it is trusted.

The rule: any change to a system's status, a blocker opening or closing, a schema version bump, or a catalogue count moving triggers an update and a push in the same working session as the change. Never batch it for later.

What to update, in order

  1. Re-measure the live place first. Never edit a status from memory or from documentation — the docs have drifted twice already. Read it out of Studio.
  2. Update the row — status pill, notes, and anything the change invalidates elsewhere on the page.
  3. Update the summary tiles and the measured date in the header.
  4. Commit and push. The site redeploys on push, usually within a minute.
  5. Mirror it into the repo docs — docs/PROGRESS.md and docs/INSTANCE-MANIFEST.md stay the detailed record; this page is the summary view over them.

Accuracy rules for this page

  • Measured, never assumed. Every number here came out of the running place. If a value cannot be measured, say so rather than estimating it.
  • A green row is a claim you can be held to. "Built but never played" is not DONE without the caveat that heads this page.
  • Record deviations, do not quietly absorb them. Two on this page — the archipelago and the duplicate-conversion rates — ship knowingly and say so.
  • When documentation and the live place disagree, the live place wins and the doc gets fixed. Two such drifts are recorded above.
